# ITHub Test Account

พื้นที่นี้ใช้บอกวิธีเตรียมบัญชีสำหรับ automated/manual testing โดย **ห้ามเก็บรหัสผ่านจริงในไฟล์ที่ Git ติดตาม**

## สิ่งที่ต้องเตรียม

บัญชีหลักที่ชุด Playwright ใช้ควรเป็นสมาชิกธรรมดา (`role=user`) และมีคุณสมบัติดังนี้:

- ไม่ใช่บัญชีจริงของผู้ใช้หรือผู้ดูแล
- ไม่ถูกแบน
- สร้างและลบกระทู้ของตัวเองได้
- กดถูกใจและบันทึกกระทู้ได้
- แก้ไขโปรไฟล์ได้
- ใช้กับ **ฐานข้อมูลทดสอบแยกจาก production เท่านั้น**

ตัวแปรที่ tests อ่าน:

```dotenv
ITHUB_E2E_EMAIL=your-test-account@example.com
ITHUB_E2E_PASSWORD=replace-with-test-password
```

ให้ใส่ค่าจริงใน `.env.local` ที่ root ของโครงการ ซึ่งถูก `.gitignore` ไว้แล้ว ไม่ต้องใส่รหัสผ่านลงใน Markdown

## ขั้นตอนสำหรับเจ้าของโครงการ

1. สร้างฐานข้อมูลหรือ environment สำหรับ E2E โดยเฉพาะ
2. รัน migration และ seed กับฐานข้อมูลทดสอบ
3. สร้างบัญชีสมาชิกธรรมดาที่ไม่ใช้ข้อมูลส่วนตัวจริง
4. ใส่ email/password ใน `C:\client\.env.local`
5. ยืนยันว่า `.env.local` ไม่ปรากฏใน `git status`
6. แจ้งผู้ทดสอบว่า environment พร้อม โดยไม่ต้องส่งรหัสผ่านผ่านแชตถ้าผู้ทดสอบเข้าถึงไฟล์ local ได้อยู่แล้ว

## สิ่งที่ชุดทดสอบจะเปลี่ยน

- login/logout ด้วยบัญชีนี้
- สร้างกระทู้ชื่อขึ้นต้น `Playwright topic` แล้วพยายามลบใน `finally`
- กด like/bookmark แล้วพยายามคืนสถานะเดิมใน `finally`
- ส่งฟอร์มแก้โปรไฟล์ด้วยรหัสผ่านเดิมที่ตั้งใจให้ผิด เพื่อยืนยันว่า username ไม่ถูกแก้บางส่วน
- authorize private Pusher channel ของบัญชี

หาก process ถูกหยุดกลางคัน อาจเหลือกระทู้หรือสถานะทดสอบไว้ จึงต้องใช้บัญชีและฐานข้อมูลที่ล้างได้

## ไฟล์บันทึกส่วนตัว

กรอกข้อมูลจริงใน `credentials.local.md` ที่เตรียมไว้ในโฟลเดอร์นี้ ไฟล์ดังกล่าวถูก ignore และห้าม force-add เข้า Git ส่วน [`TEST_ACCOUNT_TEMPLATE.md`](./TEST_ACCOUNT_TEMPLATE.md) เป็นตัวอย่างโครงสร้างที่ไม่มีความลับและเก็บใน repository ได้

บัญชี admin ยังไม่จำเป็นสำหรับ test suite ปัจจุบัน หากเพิ่มในอนาคตควรใช้คนละบัญชีกับ member และจำกัดเฉพาะ test environment
